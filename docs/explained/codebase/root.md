# The repository root

> Part of the [codebase guide](index.md). Every file below is described in plain words; the [architecture page](../architecture.md) explains how the parts work together.

The top of the repository holds no application code. It holds the settings every package shares, the commands everyone runs, the CI pipeline, the git hooks, and the Docker stack the apps talk to while you develop.

The two files to know first are `package.json`, whose scripts are the commands you type (`pnpm dev`, `pnpm test`, `pnpm db:migrate` and so on), and `.env.example`, the template for the one settings file every app and container reads.

The big kit's Docker stack has more containers, most behind opt-in profiles: pgBouncer, two Redis instances, Loki and Alloy for logs, ClickHouse for analytics, a read replica, a second database node and a cold-storage bucket. `plans/` holds the backlog, the handoff note and every finished plan.

This page covers 48 files.

## Every file

### The top level

| File | What it does |
|---|---|
| `.editorconfig` | Tells every editor the same basics: UTF-8, LF line endings, two-space indents, a final newline. |
| `.env.example` | The template for `.env`, the one settings file every app and the Docker stack read. Every key has a working local value and a comment saying what it does. Copy it to `.env` to run anything. |
| `.gitattributes` | Forces LF line endings in the repository so Windows checkouts behave like Linux, marks images and fonts as binary, and hides the lockfile from diffs. |
| `.gitignore` | What git never tracks: `node_modules`, build output, `.env`, generated route trees, logs. |
| `.lintstagedrc.js` | Settings for the pre-commit hook: which staged files get `biome check`, split into chunks so Windows' command-line length limit is never hit. |
| `.nvmrc` | The Node.js version to use (24), for `nvm use`. |
| `AGENTS.md` | The short brief any AI coding tool reads first: what the project is, the handful of rules that cost most when broken, and where the full rulebook lives. |
| `CLAUDE.md` | Claude Code's entry file. It pulls in `AGENTS.md` and every rule file in `docs/ai/rules/` so the whole rulebook is loaded at the start of a session. |
| `README.md` | The front page: what the kit is, how to run it locally step by step, the ports, the first sign-in, and what to do when it does not start. |
| `biome.json` | Root Biome settings. It only extends the shared config in `tooling/biome-config`. |
| `commitlint.config.js` | The commit message rules: conventional commits with a closed list of scopes, one per package or area. A commit naming an unknown scope is rejected. |
| `eslint.config.js` | Root ESLint settings. It only re-exports the shared config from `tooling/eslint-config`. |
| `package.json` | The workspace's root manifest. It holds no code, only the commands everyone runs: `pnpm dev`, `build`, `test`, `lint`, `check:architecture`, `infra:up`, `db:migrate`, `db:seed`, `guide:publish` and the rest. Each one delegates to a package or a script. |
| `pnpm-lock.yaml` | Generated by pnpm. The exact version of every installed dependency, so every machine installs the same tree. Never edited by hand. |
| `pnpm-workspace.yaml` | Declares the workspace (`apps/*`, `packages/*`, `tooling/*`) and the catalog: the single place every dependency version is written. Packages refer to it with `catalog:` instead of their own version ranges. |

### `.github/workflows/`

| File | What it does |
|---|---|
| `ci.yml` | The CI pipeline on GitHub. The `verify` job installs, builds, type-checks, lints, migrates a real Postgres, runs every test, boots each app once and runs the architecture and contrast checks. The `compose` job starts the whole Docker stack and runs the smoke tests against it. The `audit` job reports known-vulnerable dependencies. |

### `.husky/`

| File | What it does |
|---|---|
| `commit-msg` | Git hook. Checks each commit message against the commit convention (`commitlint.config.js`) and rejects it if it does not match. |
| `pre-commit` | Git hook. Formats and lints only the files being committed (through `.lintstagedrc.js`). |
| `pre-push` | Git hook. Before a push, runs the fast checks: Biome, ESLint, the architecture check and the colour-contrast check. Type-checking and tests stay in CI because they take minutes. |

### `infra/`

| File | What it does |
|---|---|
| `alloy.config.alloy` | Settings for Grafana Alloy, the log shipper. It reads every container's output, parses the app's JSON log lines, attaches the four allowed labels and sends them to Loki. |
| `docker-compose.yml` | The local stack, as Docker containers. It defines Postgres with pgvector, Redis, MinIO (S3-compatible file storage) with a one-shot bucket setup, and Mailpit (a fake mail inbox). The big kit adds pgBouncer, a second Redis, Loki and Alloy for logs, ClickHouse, a read replica, a second database node and a cold-storage bucket, most behind opt-in profiles. |
| `loki.config.yml` | Settings for Loki, the log store: where it keeps data and that it deletes logs after 30 days. |
| `pg_hba.conf` | Postgres access rules for the big kit's replica setup: which hosts may connect, and that the replica may stream changes from the primary. |
| `postgres.init.sql` | Runs once when the Postgres container is first created. It turns on the extensions the app needs: `vector` (embeddings), `pg_trgm` (fuzzy text matching), `uuid-ossp` and `pg_stat_statements` (which queries are slow). |
